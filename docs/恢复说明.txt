四、构建环境的两个坑（务必记住）
-------------------------------------------------
坑 A：代理
  本机 ~/.gradle/gradle.properties 里写死了 systemProp.http.proxyHost=127.0.0.1:10808。
  该代理（v2rayN）未启动时，Gradle 会表现为“插件找不到 / 依赖解析失败”，
  极易误判为仓库问题。绕过：
    .\gradlew.bat build "-Dhttp.nonProxyHosts=*" "-Dhttps.nonProxyHosts=*"

坑 B：26.3 不再混淆
  官方 26.3 版本清单只有 downloads.client / downloads.server，没有 mappings；
  maven.fabricmc.net 上也没有 26.3 的 intermediary（404）。
  因此 loom.officialMojangMappings() 必然报
  “Failed to find official mojang mappings for 26.3”。
  解决办法：恒等映射 mappings/identity.tiny（official 与 named 同名），并用
    mappings loom.layered {
       mappings(FileSpec.createFromFile(file('mappings/identity.tiny'))) {
          fallbackNamespaces('official', 'named')
       }
    }
  注意：file(...) 不是 builder 的方法，方法是 mappings(...) 且必须传 FileSpec 对象，
  不能传字符串（会被当成 Maven 坐标）。
  副作用：没有 intermediary 命名空间，remapSourcesJar 会失败，已在 build.gradle 中禁用。

坑 C：JDK
  26.3 的 javaVersion 是 25，用 JDK 21 直接报
  “Dependency requires at least JVM runtime version 25”。
  本机 jdk-25.0.3.9-hotspot 可用，构建前把 JAVA_HOME 指过去。
