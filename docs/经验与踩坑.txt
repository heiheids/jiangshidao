-------------------------------------------------
坑 1：背面剔除时“世界法线”与“相机空间方向”混用（最严重）
-------------------------------------------------
现象：第一版渲染出来，模型像被炸开一样——帽子拉出长条平面、
      身体缺失大块、整个人变成碎片。
原因：我把面的世界坐标法线直接和“相机空间中的视线向量”做点乘：
        const viewDir = V.norm(camPts[0]);      // 相机空间
        const facing = V.dot(f.normal, viewDir); // f.normal 是世界空间
      两个不同坐标系做点乘，结果毫无意义，导致随机剔除。
修复：先把法线变换到相机空间再判断：
        const nc = [dot(n,cam.r), dot(n,cam.u), dot(n,cam.f)];
        const facing = dot(nc, norm(camPts[0]));
排查手法（值得保留）：写了 tools/render/debug-geo.js，把所有面替换成
      纯色（+Z 蓝 / -Z 绿 / +X 红 / -X 青 / +Y 黄 / -Y 紫），
      一眼就能看出是“几何错”还是“UV 错”。强烈建议保留这个调试脚本。

-------------------------------------------------
坑 2：贴图打包时误以为“面尺寸小数”可以直接用
-------------------------------------------------
现象：图集里出现重叠条带，渲染时颜色互相污染。
原因：面尺寸来自世界坐标差值，可能是 2.05 这样的浮点数，
      打包器按浮点算宽度，导致相邻矩形算出相同像素区间。
修复：packFaces 里统一 Math.ceil 到整数像素，并给每个矩形留 1px padding。

-------------------------------------------------
坑 3：手臂用“上臂+小臂两段分别旋转”会得到生硬的 L 形
-------------------------------------------------
做僵尸前伸手臂时，如果分别旋转 upperArm 和 foreArm，
肩部会出现明显折角，且袖子的接缝无法对齐。
正确做法：把整条手臂（袖子+袖口+手掌+手指，共 8 个盒子）定义在
      一个以肩关节为原点的局部坐标系里，再整体绕 pivot 前伸 84°。
      数据上只写一个 xform = { pivot:[±5.6,26.4,0], rot:[-84,±1.5,0] }。
后续写 Java 的 EntityModel 时，同理应该把整条手臂放在同一个
      ModelPart 下，用 xRot 控制，而不是拆开。

-------------------------------------------------
坑 4：手指做得太碎反而难看
-------------------------------------------------
最初每根手指做了“中段 + 指尖”两块，共 6 块，渲染出来像玉米棒。
方块风模型的细节上限很低：手指用 3 根（每根 1 块）+ 1 块共用指尖即足够。
判断标准：单个盒子的最小边不要小于 0.6 单位，否则在游戏里会被
      抗锯齿糊成一团，还白白增加面数。

-------------------------------------------------
坑 5：红色镶边很容易“糊满全身”
-------------------------------------------------
第一次实现长袍时把裙摆四面都包了红边，结果整个下半身变成红桶，
完全丢掉了参考图里“石青为主、红边为辅”的气质。
正确比例：红边宽度控制在总宽的 10%~15%，且只在
      · 前襟两侧竖条
      · 下摆一圈
      · 袖口一圈
      · 领口一圈
      这四处出现，其余全部留给石青色。

-------------------------------------------------
坑 6：PowerShell 与 UTF-8
-------------------------------------------------
本工程所有文本文件写入均通过 Node.js 的 fs.writeFileSync(path, text, 'utf8')
或在 pwsh 中显式设置：
    $OutputEncoding = [Text.UTF8Encoding]::new($false)
    [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
绝不要用 Get-Content / Set-Content / Out-File 的默认编码处理中文文件，
否则会产生 BOM 或乱码，导致后续读取失败。
本次全部中文文档（使用说明 / 技术说明 / 本文件）均为无 BOM UTF-8。

-------------------------------------------------
坑 7：工程环境缺失导致“先搭 Gradle 再验证模型”是错误顺序
-------------------------------------------------
本机 Java 只有 17（1.21.1 需要 21），且没有 gradle 命令。
如果一开始就强行搭 NeoForge 工程，会先卡在环境下载上，几十分钟都
看不到模型长什么样。正确顺序：先让用户确认造型，再补环境。
造型阶段用零依赖的 Node 渲染器，成本低、迭代快（每次渲染 < 1 秒）。

-------------------------------------------------
经验：渲染速度
-------------------------------------------------
800×800 画布、234 个面、5 个机位，全部渲完约 0.6 秒（纯 JS 单线程）。
所以完全不需要 GPU / three.js / 任何第三方渲染库，
     自己写 300 行光栅化就够了，还省去了 npm 安装与联网风险。
