# 桃子（桃树叶结果）

> 作者：黑山大叔
> 主页：https://space.bilibili.com/19428259
> GitHub：https://github.com/heiheids

## 玩法

自然生长的桃树叶会结出桃子，成熟后叶片表面显示粉红果实，右键摘下。

## 结果条件

| 条件 | 说明 |
|---|---|
| **必须自然生长** | 玩家放置的桃叶（`PERSISTENT=true`）永不结果 |
| **必须有树干相连** | 与桃树原木断开后由原版腐烂机制移除，自然消失 |
| **至少一面外露** | 六面中任一相邻格为空气 |
| **光照 ≥ 9** | 与浆果丛一致 |
| **概率 1/5** | 每次随机刻，节奏参考浆果丛 |

## 关键实现点

### 1. 必须覆盖 isRandomlyTicking

原版 `LeavesBlock.isRandomlyTicking` 只在 `DISTANCE == 7`（即将腐烂）时返回 true ——
**正常长在树上的叶子根本不参与随机刻**。

因此本模组的桃叶改为：

```java
public boolean isRandomlyTicking(BlockState state) {
   return !state.getValue(PERSISTENT);   // 自然树叶都参与随机刻
}
```

如果漏了这一步，结果逻辑写在 randomTick 里也永远不会执行。

### 2. 默认状态必须在父类基础上追加

```java
// 正确
this.registerDefaultState(this.defaultBlockState().setValue(HAS_PEACH, FALSE));

// 错误：会丢掉父类的 DISTANCE=7 / WATERLOGGED=false，导致树叶"含水"
this.registerDefaultState(this.stateDefinition.any().setValue(HAS_PEACH, FALSE));
```

### 3. 物品模型用 item/generated

物品图标用 `minecraft:item/generated` + `layer0`，整张贴图即图标，
不涉及 UV 采样，避免立体模型在 GUI 里比例失调。

### 4. 方块覆盖层的贴图变量必须在 textures 里定义

```json
"textures": { "peach": "jiangshidao:block/peach_leaves_peach" },
"faces": { "north": { "texture": "#peach" } }
```

直接写贴图路径或引用未定义变量（如 `#missing`）都会导致紫黑方块，
日志会报 `Missing texture references in model ...`。

## 桃子物品

- 食物属性：**8 饱食度 / 4.8 饱和度**（苹果 4 / 2.4 的两倍）
- 堆叠 64
- 创造模式物品栏可见

## 相关文件

| 文件 | 作用 |
|---|---|
| `block/PeachLeavesBlock.java` | 结果逻辑、右键采摘、方块状态 |
| `block/PeachSaplingBlock.java` | 树苗可种植地面判定 |
| `block/PeachTreeGrower.java` | 生成桃树（树干+树叶） |
| `models/item/peach.json` | 物品图标模型（generated） |
| `models/block/peach_leaves_peach.json` | 叶片 + 五面桃子覆盖层 |
| `textures/item/peach.png` | 物品图标 16×16 |
| `textures/block/peach_leaves_peach.png` | 覆盖层贴图 |
| `blockstates/peach_leaves.json` | 按 has_peach 分变体 |

## 生成脚本

```powershell
pwsh -NoProfile -File tools\ops\gen-peach-textures.ps1    # 生成两张贴图
```

## 可调参数

`PeachLeavesBlock.java` 中：

- `GROW_CHANCE = 5` —— 结果概率分母，改小则更快
- `MIN_LIGHT = 9` —— 最低光照
